# ZEN 3D explainer project

Treat a request such as "create a story using the animation style you downloaded about …" as a request to use this production system.

Read [SKILL.md](SKILL.md), then [references/STYLE_BIBLE.md](references/STYLE_BIBLE.md). Read the relevant reports linked there. Inspect reference frames/contact sheets before choosing a look. All frame numbers are zero-based; all frame intervals have exclusive ends.

Preserve full 3D geometry, cutaway world continuity, smooth 30 fps absolute-time animation, clear narration timing, neutral/earthy buildings, saturated green foliage and readable material layers. Do not import the upstream bean-head characters, thick world ink, march score, compulsory 67-second length, forbidden-captions rule or historical-story formula.

Create an ORIGINAL story. Use these references as visual evidence, not as a script or brand to reuse. Existing construction claims in the transcripts are reference content, not a fact source for a new engineering explanation. Verify factual claims independently when they matter to a new story.

Use the new brief to choose duration. Default to 45–65 seconds for a medium explainer and 4.2–4.4 spoken words/second including pauses. Use one original narrator identity. Never fabricate a real voice ID, API key, waveform, audio transcript or completed render. If voice generation is unavailable, finish the scene/script, clearly mark narration as pending and state the one missing dependency.

Render and inspect a representative wide, section and close-up before making the full film. Run typecheck and every-frame QA. Render several frames in shuffled order to check deterministic posing. Record validation in `out/<story>/VALIDATION.md` with any remaining limitations. Deliver a finished MP4 only after checking its actual dimensions, frame rate, duration and audio presence.

The starter is intentionally an original simplified 12-second silent motion study. Replace its timeline, scene layout, captions and mechanisms for the new topic. Its front-mounted pipe is an illustrative open-section diagram, not an engineering design. The style reports are the visual target; a successful build/typecheck alone is not evidence of a close style match.

Do not upload `node_modules`, credentials, caches or output renders to a new repository. Reference MP4s and study frames are included at the user's request and retain separate media rights. Do not assume the repository's software license grants reuse rights to those videos, logos or voice performances.
